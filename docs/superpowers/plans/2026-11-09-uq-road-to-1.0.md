# uQ: road to 1.0

## Context

You asked what must be done before a full release. You chose:
- **1.0 = all five phases of the design** (`docs/superpowers/specs/2026-11-08-uq-desktop-design.md` §7);
- **distribution through the AUR, built from tagged GitHub Releases.**

Each phase already ends in a usable daily driver, so the route is a series of tagged pre-releases,
each passing a live-session gate, ending in 1.0.

**Where things stand (2026-11-09):**
- **Phase 1** (foundation) is done.
- **Phase 2** (shell), slices 1–5, is all coded on `phase2-shell`, 96 commits ahead of `main`.
  - Slice 5's final fix wave landed as `41a36f8`; it is not yet re-reviewed or pushed.
  - CI is green up to `0b30259`.
  - The headless smoke test has skipped on every slice, so nothing has run on real Hyprland yet.
- **Phase 3** (settings) has an approved spec (`docs/superpowers/specs/2026-11-08-uq-phase3-settings-design.md`)
  with six slices, and no plans yet.
- **Phases 4 and 5** have no specs.
- **Packaging:**
  - `packaging/uq/PKGBUILD` builds from the local checkout (`cd "$(_root)"`) at `pkgver=0.1.0`.
  - There are no git tags and no release workflow; `.github/workflows/ci.yml` is the only workflow.

**The success criteria 1.0 must meet** (design §1):
1. A fresh Arch install plus `pacman -S uq` (or bindle's uq profile) gives a themed desktop on next
   login.
2. Theme and variant changes re-theme everything live.
3. Layouts survive reload and reboot.
4. uQ runs with none of the integrated apps installed; each one installed adds its pieces
   automatically.

## Milestones

Every milestone ends at the **release gate** (below) and a tag. Each phase follows the same
pipeline used so far:
1. a spec, written with the brainstorming skill, where none exists;
2. one plan per slice, written with the writing-plans skill;
3. subagent-driven execution with a task review after each task and a final whole-branch review;
4. CI green;
5. the live checklist.

### M0: Close Phase 2 → tag `v0.2.0` (first public pre-release)

1. **Finish slice 5.**
   - Do the scoped re-review of `41a36f8` against
     `.superpowers/sdd/2026-11-09-uq-phase2-slice5-lock-idle-power/final-fixes.md`.
   - Push, confirm CI is green, and close the ledger.
2. **Live Hyprland pass on your machine.** This is the biggest open risk. Work through:
   - `docs/notes/lock-idle-live-check.md`;
   - `docs/notes/notifi-hyprland-check.md` (report noti-fi problems to the noti-fi repo);
   - the slice 3 checks: Wi-Fi scan on and off with the panel, open networks shown as Open,
     Bluetooth connect, no scroll jitter, the schedule toggle;
   - the slice 2 SUPER-tap check on 0.56.2.

   Fix what it finds, one small fix plan per cluster of failures.
3. **Make smoke testing real.** CI's headless Hyprland crashes at `CBackend::create()`.
   - Either make `scripts/smoke-shell.sh` run (a Hyprland headless backend flag or env, or a VM
     runner),
   - or turn it into a documented manual pre-release script run in a VM.

   Either way, every release gate needs a non-desktop run.
4. **Real package install.**
   - Change the PKGBUILDs to build from a tagged tarball: `source=("$url/archive/v$pkgver.tar.gz")`
     plus checksums.
   - Run `makepkg -si` in a clean chroot (`extra-x86_64-build`), then `uqctl setup` on a fresh
     user account.
   - Confirm all of these land correctly:
     - `lock/` with its `core`/`logic` symlinks;
     - `uq-lock.service`;
     - `/usr/lib/uq/uq-lock-run`;
     - the PAM files and `backup=()`;
     - `shell/` and both user units.
5. **Clear the deferred minors.**
   - Triage the deferred lists in each slice ledger (slices 3–5) and fix what the final reviews
     marked "before merge".
   - Delete the slice workspaces once their records are in git.
6. **Merge `phase2-shell` into `main`.** Use a PR, with CI on the PR.
7. **Release setup**, done once and reused from here on:
   - **Versioning:** the workspace version in `Cargo.toml` and `pkgver` move together. Add a
     `scripts/bump-version.sh` and a CI check that they match.
   - **Changelog:** a `CHANGELOG.md`, with each milestone's notes taken from the plans and ledgers.
   - **Release workflow:** `.github/workflows/release.yml`. On a `v*` tag it:
     - runs the full CI;
     - builds the source tarball;
     - builds `uq` and `uq-hyprland-pin` in an Arch container;
     - creates a GitHub Release with the notes, the tarball and the `.pkg.tar.zst` files;
     - prints the `.SRCINFO` and checksum update for the AUR.
   - **AUR:**
     - create the `uq` and `uq-hyprland-pin` AUR repos (your account, done by you);
     - keep the `PKGBUILD` and `.SRCINFO` mirrored in `packaging/`;
     - push the AUR repos for each tag, by hand or through an AUR deploy action with an SSH key
       you add as a secret.
   - **Hyprland pin:** re-check the 0.56.2–0.57.x pin against current Arch and Manjaro at each
     release, and widen it only after `verify_config` passes on the new version.
8. Tag **`v0.2.0`** as a pre-release and publish it to the AUR.

### M0b: bindle installs uQ by default (decided 2026-11-09)

uQ is now bindle's default recommended desktop. Until the full Phase 5 hand-off exists, bindle
needs a minimal path that works with `v0.2.0`. Its order matters: bindle may only *recommend* uQ
once `uq` and `uq-hyprland-pin` install from the AUR.

1. **In bindle** (its own repo and release):
   - a `uq` entry in `catalog/desktops.toml`, marked as the default recommendation;
   - its packages: `uq` and `uq-hyprland-pin` from the AUR, plus uQ's optdepends as essentials
     (kitty, the theme fonts and icons, papirus, bibata, wireplumber, playerctl, networkmanager,
     bluez, power-profiles-daemon, fprintd when a reader is detected);
   - the per-user step `uqctl setup` for the installing user;
   - a greeter until `uq-greeter` exists: greetd with tuigreet, or SDDM, starting the Hyprland
     session;
   - detection of an existing uQ install (`detect = "uq"`).
2. **In uQ:**
   - make `uqctl setup` safe to run unattended and idempotent, with non-zero exit codes bindle can
     act on;
   - document the "installed by bindle" path in the README;
   - add bindle's install to the M0 live pass: a fresh Arch VM, archinstall, then bindle with the
     uQ default, then reboot into a themed uQ.
3. **Gate:** bindle's release that flips the default ships only after uQ `v0.2.0` is on the AUR
   and that VM run passes. Until then bindle can offer uQ as an option labelled preview.

### M2: Phase 4, repo integrations → `v0.4.0` … `v0.4.x`

   - the `uq-tokens` web snippet;

### M4: Release hardening → `v1.0.0-rc.N` → `v1.0.0`

- **Full regression in a VM** across all phases:
  - every live checklist in `docs/notes/`;
  - the spec success criteria for Phase 2, Phase 3 and the design as a whole;
  - multi-monitor, hot-plug, suspend and resume, a battery laptop, and a fingerprint reader.
- **Security pass over the whole tree:** the lock and PAM, the polkit helper, the bridge's input
  limits, the notification sanitiser and the provider API. Use `/code-review` at a high level, or
  `/security-review`.
- **Upgrade path:** going from `v0.5` to 1.0 keeps `state.toml`, the user's `user.lua` and the
  PAM files (`backup=()`). A Phase 1 `state.toml` still loads.
- **Docs:**
  - the README covers installing (AUR), first run, every keybind, every `uqctl` command,
    troubleshooting (masking other notification daemons, the recovery bind) and uninstalling;
  - man pages, or `--help` coverage, for `uqctl`;
  - a `SECURITY.md` with a contact.
- **Release candidates:** at least one `rc` that you run as your daily driver for a set period
  (suggested: one week) with no lock or session regressions. Then tag `v1.0.0` and publish to the
  AUR.

## Release gate (every tag)

1. CI is green on `main`: fmt, clippy, cargo tests, QML tests, shell tests and `verify_config`.
2. The smoke run passed in CI or the VM.
3. The milestone's live checklist is complete, with no open Critical or Important issues.
4. A clean-chroot package build passed, plus a fresh-user install.
5. The CHANGELOG is written, the version is bumped everywhere, and the Hyprland pin is
   re-verified.
6. Tag → release workflow → GitHub Release → AUR push.

## Critical files

- **Packaging:** `packaging/uq/PKGBUILD`, `packaging/uq-hyprland-pin/PKGBUILD`, `packaging/*.service`,
  `packaging/uq-lock-run`, `packaging/pam/*`.
- **CI:** `.github/workflows/ci.yml` (extend) and a new `.github/workflows/release.yml`.
- **Versioning:** `Cargo.toml` (workspace version); new `CHANGELOG.md` and
  `scripts/bump-version.sh`.
- **Smoke tests:** `scripts/smoke-shell.sh` and the `tests/shell/*.sh` loop.
- **Live checklists:** `docs/notes/*.md`.
- **Specs:** `docs/superpowers/specs/*`; new Phase 4 and Phase 5 specs go there.
